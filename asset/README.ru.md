## 📖 Введение

ElasticLens - это **платформа визуализации и анализа** результатов инспекции кластеров Elasticsearch. Система разработана для обработки диагностических ZIP-пакетов, экспортированных из **официального диагностического инструмента Elasticsearch**, автоматического анализа диагностических данных, глубокого анализа состояния здоровья кластера и генерации многомерных отчетов инспекции (HTML / Word / JSON).

Эта платформа помогает операционному персоналу быстро понимать состояние здоровья кластера, обнаруживать потенциальные проблемы и получать рекомендации по оптимизации через интуитивно понятные визуальные отображения, устраняя необходимость вручную анализировать сложные диагностические данные.

**Официальный диагностический инструмент Elasticsearch**: [elastic/support-diagnostics](https://github.com/elastic/support-diagnostics/)

### ✨ Основные возможности

- 🌐 **Веб-платформа** - Полнофункциональное веб-приложение на основе React + Flask, поддерживающее перетаскивание для загрузки диагностических пакетов
- 📊 **Многоформатные отчеты** - Автоматическая генерация отчетов инспекции в форматах HTML и Word (.docx)
- 🔍 **Интеллектуальный анализ** - Автоматический анализ диагностических ZIP-пакетов ES, извлечение ключевых метрик (здоровье кластера, ресурсы узлов, детали индексов, ILM, снимки, безопасность и т.д.)
- 🧠 **Глубокий анализ** - Оценка здоровья на основе механизма правил, анализ ресурсов и генерация оповещений
- 🎯 **Оценка здоровья** - Количественная оценка 0-100 для интуитивного отображения уровней здоровья кластера
- 🔔 **Градуированные оповещения** - Механизм оповещений трех уровней/двух уровней/одного уровня (severity_level)
- ⚡ **Асинхронная обработка** - Фоновая асинхронная обработка задач, поддерживающая загрузку больших файлов (2 ГБ) и длительный анализ
- 📈 **Визуализация** - Круговая панель оценки здоровья, прогресс-бары, карточки и другие визуальные отображения
- 📝 **Многоязычная поддержка** - Полная поддержка упрощенного китайского, традиционного китайского, английского, японского, французского, немецкого, русского - семи языков, с автоматическим переключением интерфейса и отчетов

- **npm**: 9+ (управление пакетами frontend)

Используйте Docker Compose для развертывания сервисов frontend и backend одним кликом:

```bash
# Выполнить в корневом каталоге проекта
cd elasticlens

# Запустить все сервисы (frontend + backend)
./start.sh

docker compose up -d
```

- Интерфейс Frontend: http://localhost:8080
- API Backend: http://localhost:5001

- ✅ Автоматически обрабатывает все зависимости

- ✅ Проверки работоспособности и автоматический перезапуск

#### Традиционное развертывание (Локальная разработка)

##### 1. Установка зависимостей Backend

```bash
cd backend
pip install -r requirements.txt
```

Зависимости backend включают:
- Flask 3.0.0 - Веб-фреймворк
- Flask-CORS 4.0.0 - Поддержка cross-origin
- python-docx >= 1.0.0 - Генерация отчетов Word
- loguru 0.7.2 - Управление журналами
- weasyprint >= 60.0 - Рендеринг PDF (опционально)
- SQLite3 - База данных (встроена в Python, нулевая конфигурация)

#### 2. Установка зависимостей Frontend

```bash
cd frontend
npm install
```

Зависимости frontend включают:
- React 18.2 + TypeScript
- Ant Design 5.12 - Библиотека компонентов UI
- Vite 5.0 - Инструмент сборки
- Axios 1.6 - HTTP-клиент
- Zustand 4.4 - Управление состоянием
- Recharts 2.10 - Библиотека графиков

##### 3. Запуск сервисов

**Запуск Backend** (в корневом каталоге проекта):
```bash
cd backend
python app.py
```
Сервис backend работает на `http://localhost:5000`

**Запуск Frontend** (в корневом каталоге проекта):
```bash
cd frontend
npm run dev
```
Сервис frontend работает на `http://localhost:5173`

#### 4. Использование веб-платформы

1. Откройте браузер на `http://localhost:5173`
2. Перетащите или нажмите для загрузки диагностического ZIP-файла ES
3. Дождитесь завершения асинхронного анализа
4. Просмотрите отчет инспекции (отображение HTML)
5. Нажмите кнопку "Скачать Word" для экспорта отчета в формате Word

## 📊 Обзор пунктов инспекции

Система охватывает **11 основных категорий** показателей инспекции, включая **30+ конкретных проверок**:

| Категория | Вес | Пункты проверки |
|-----------|-----|-----------------|
| **Здоровье кластера** | 30% | Статус кластера, доля активных шардов, неназначенные шарды, инициализируемые шарды, перемещаемые шарды |
| **Ресурсы узлов** | 25% | Использование диска, использование кучи JVM, использование CPU, системная нагрузка, шардов на узел |
| **Здоровье индексов** | 20% | Распределение здоровья индексов, количество больших индексов, индексы с высоким количеством сегментов, индексы с высоким количеством шардов, индексы с большим количеством документов |
| **Проверки шардов** | 5% | Размер одного шарда, количество документов одного шарда, баланс распределения шардов |
| **Проверки восстановления** | 5% | Количество восстанавливаемых шардов, средний прогресс восстановления |
| **Политика ILM** | 3% | Проверка статуса ILM |
| **Проверка снимков** | 3% | Конфигурация и статус снимков |
| **Проверка безопасности** | 2% | Включение функций безопасности X-Pack |
| **Шаблоны и маппинги** | 2% | Шаблоны индексов, шаблоны компонентов, среднее количество полей |
| **Журналы и ошибки** | 2% | Количество GC, статистика времени GC |
| **Информация о производительности** | - | Общее количество документов кластера, общий размер хранилища кластера (отображение информации, не включается в оценку) |

## ⚙️ Конфигурация

### Конфигурация порогов

Основной файл конфигурации порогов находится по адресу `configs/checkpoints_thresholds_complete.yaml`, основные элементы конфигурации:

```yaml
# Здоровье кластера
cluster:
  status:
    green: none     # Статус ЗЕЛЕНЫЙ без оповещения
    yellow: warning # Статус ЖЕЛТЫЙ предупреждение
    red: critical   # Статус КРАСНЫЙ критический
  active_shards_percent:
    warning: 95     # Ниже 95% предупреждение
    critical: 90    # Ниже 90% критический

# Ресурсы узлов
node:
  disk_usage_percent:
    warning: 70     # Диск 70% внимание
    alert: 80       # Диск 80% водяной знак
    critical: 85    # Диск 85% отказ записи
  heap_used_percent:
    warning: 70     # JVM 70% внимание
    critical: 85    # JVM 85% риск OOM

# Здоровье индексов
index:
  size_gb:
    warning: 50     # Один индекс 50 ГБ внимание
    critical: 100   # Один индекс 100 ГБ критический
  docs_count:
    warning: 100000000    # 100M документов внимание
    critical: 500000000   # 500M документов критический
```

### Расчет оценки здоровья

```python
Оценка = 100 - (Критические оповещения × 20) - (Предупреждения × 5) - (Информационные × 1)
Диапазон оценки: 0-100
```

| Диапазон оценки | Уровень здоровья |
|-----------------|------------------|
| 90-100 | 🌟 Отлично |
| 75-89 | 👍 Хорошо |
| 60-74 | ⚠️ Удовлетворительно |
| 40-59 | 🔴 Плохо |
| 0-39 | 🚨 Критично |

## 📄 Вывод отчетов

### Отчет HTML

- Дизайн темы с фиолетовым градиентом
- Круговая визуализация оценки здоровья
- Адаптивная макет карточек
- Градуированное отображение информации об оповещениях (Critical/Warning/Info)
- Полная таблица деталей пунктов проверки

### Отчет Word (.docx)

- Профессиональный формат макета
- Таблица базовой информации кластера
- Оценка здоровья и оценивание
- Детали пунктов проверки (статус прохождения/непрохождения, значения, пороги)
- Градуированный список деталей оповещений
- Цветовая кодировка (✅ Зеленый пройдено, ❌ Красный не пройдено)

### Отчет JSON

- Структурированные данные
- Включает полные детали пунктов проверки `check_results`
- Удобно для вторичной разработки и анализа данных

## 🔧 API-эндпоинты

Backend предоставляет следующие REST API-эндпоинты:

### Управление задачами

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| POST | `/api/v1/upload` | Загрузить диагностический ZIP-файл, создать асинхронную задачу |
| GET | `/api/v1/tasks` | Получить список задач ( paginated, исключить удаленные) |
| GET | `/api/v1/tasks/<task_id>` | Получить детали одной задачи |
| DELETE | `/api/v1/tasks/<task_id>` | Мягкое удаление задачи (каскадное удаление отчетов) |

### Управление отчетами

### Распространенные проблемы

#### 1. Сбой генерации отчета Word
```bash
# Проверить, установлен ли python-docx
pip install python-docx>=1.0.0
```

#### 2. Сбой запуска Frontend
```bash
# Убедиться, что Node.js >= 18
node -v
npm -v

# Переустановить зависимости
cd frontend
rm -rf node_modules
npm install
```

#### 3. Порт Backend занят
```bash
# Изменить номер порта в backend/app.py
# Порт по умолчанию: 5000
```

#### 4. Порт Frontend занят
```bash
# Изменить номер порта в frontend/vite.config.ts
# Порт по умолчанию: 5173
```

#### 5. Проблемы с китайскими путями Windows
- python-docx может иметь проблемы совместимости с китайскими путями Windows
- Рекомендуется размещать проект в английском пути

#### 6. Повреждение файла базы данных
```bash
# Удалить файл базы данных, перезапуск службы автоматически восстановит его
cd backend
rm es_insight.db
python app.py
```
**Примечание**: Это приведет к потере всех исторических данных, пожалуйста, действуйте с осторожностью!

#### 7. Статус задачи не обновляется
- Проверить, нормально ли работает сервис backend (доступ к `http://localhost:5000/api/v1/health`)
- Проверить консоль браузера на наличие сетевых ошибок
- Подтвердить правильность адреса API frontend (`.env.development`)
