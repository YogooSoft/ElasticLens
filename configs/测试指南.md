# 配置文件测试指南

## 测试目的
验证巡检报告生成系统能够正确读取和应用配置文件中的各项设置。

## 配置文件位置
- **主配置文件**: `configs/checkpoints_thresholds_complete.yaml`
- **规则引擎加载**: 自动读取配置文件并应用到检查逻辑

## 测试场景

### 场景 1：集群状态配置测试

#### 测试 GREEN 状态配置
```yaml
cluster:
  status:
    green: none      # 不告警
    yellow: warning  # 警告
    red: critical    # 严重
```

**预期结果**：
- 集群状态为 GREEN 时：不产生告警
- 集群状态为 YELLOW 时：产生 warning 告警
- 集群状态为 RED 时：产生 critical 告警

**测试步骤**：
1. 修改 `green` 配置值为 `info` 或 `warning`
2. 运行：`python -m es_insight.parse_check_result`
3. 检查报告中的告警列表
4. 验证 GREEN 状态是否按配置产生相应级别的告警

---

### 场景 2：未分配分片阈值测试

#### 默认配置（推荐）
```yaml
cluster:
  unassigned_shards:
    warning: 1       # 有未分配分片时警告
    critical: 10     # 大量未分配时严重警告
```

#### 严格配置（零容忍）
```yaml
cluster:
  unassigned_shards:
    warning: 0       # 有任何未分配分片都警告
    critical: 5      # 5 个以上严重警告
```

**测试步骤**：
1. 修改 `warning` 值为 `0` 或 `1`
2. 运行检查
3. 观察告警是否按预期触发

---

### 场景 3：索引大小阈值测试

#### 当前配置
```yaml
index:
  size_gb:
    warning: 50      # 单索引超过 50GB 警告
    critical: 100    # 单索引超过 100GB 严重警告
```

#### 测试配置（更严格）
```yaml
index:
  size_gb:
    warning: 30      # 降低阈值到 30GB
    critical: 80     # 降低阈值到 80GB
```

**预期结果**：
- 更多索引会被标记为警告或严重
- 告警数量增加

**测试步骤**：
1. 修改阈值配置
2. 运行检查
3. 统计告警数量变化
4. 验证告警消息中的阈值显示

## 验证要点

### 1. 告警数量
- 修改阈值后，告警数量应该相应增减
- 阈值越严格，告警越多
- 阈值越宽松，告警越少

### 2. 告警级别
- 配置 `warning` 应该产生 🟡 警告
- 配置 `critical` 应该产生 🔴 严重告警
- 配置 `none` 或 `info` 不产生告警（或仅提示信息）

### 3. 告警消息
- 消息中应该显示正确的当前值和阈值
- 格式：`当前值：X | 阈值：Y`
- 单位应该清晰明确

### 4. 健康评分
- 告警越多，评分越低
- 严重告警扣分更多（-20 分）
- 警告告警扣分较少（-5 分）

## 常见问题

### Q1: 修改配置后告警没有变化？
**A**: 检查：
1. 配置文件语法是否正确（YAML 缩进）
2. 配置项名称是否拼写正确
3. 是否重新运行了检查命令
4. 日志中是否加载了正确的配置文件

### Q2: 告警阈值显示不对？
**A**: 确认：
1. JSON 报告中的 `threshold` 字段值
2. 文本报告中的阈值显示
3. 代码中是否正确读取了配置

### Q3: 健康评分计算不对？
**A**: 验证：
1. 告警级别是否正确（warning/critical）
2. 评分公式：100 - (critical×20) - (warning×5)
3. 最低分为 0，最高分为 100
